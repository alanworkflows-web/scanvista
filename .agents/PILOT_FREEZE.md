# Pilot Freeze Policy

This policy is active immediately and applies to all development moving forward. ScanVista is now transitioning from internal development to **External Pilot validation**.

Our priority is learning from real hospitality managers, not building speculative features.

## Allowed
- ✓ Bug fixes (e.g., resolving crashes, Edge case errors).
- ✓ Performance optimizations (e.g., image loading, bundle size).
- ✓ UX improvements driven by direct observation of user friction.
- ✓ Copy changes to improve clarity.
- ✓ Security fixes.

## Not Allowed
- ✗ **New modules** (e.g., adding Staff Management, Housekeeping).
- ✗ **New AI features** (e.g., auto-pricing, generative text, AI concierge).
- ✗ **HQ / Multi-property** architecture.
- ✗ **Integrations** (e.g., PMS, POS, Stripe) until explicitly validated as blocking friction.
- ✗ **Large redesigns**.
- ✗ **Database schema rewrites** (unless critical for an active pilot blocker).

Success is defined strictly as:
1. The manager sets up the property without intervention.
2. Guests scan the QR and find what they need.
3. No critical bugs occur.
4. The manager confirms utility: *"I'd actually use this."*
