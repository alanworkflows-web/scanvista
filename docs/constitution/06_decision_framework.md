# Decision Framework

*Every feature proposal, screen design, and AI capability must answer these questions. If a proposal fails even one critical question, do not build it.*

## 1. Problem
**What problem exists?**
- Define the exact friction point in the real world (e.g., "Managers spend 20 minutes gathering data from 3 systems just to know if they are ready for lunch service.")

## 2. User
**Who benefits?**
- Is it the GM? The Chef? The guest? Be specific. If it only benefits "the database," reconsider.

## 3. Moment
**What moment of the day?**
- Does this happen during the Morning Briefing? During Live Operations? At Handover? Every screen must map to a real-world hospitality moment.

## 4. Decision
**What decision becomes easier?**
- ScanVista is a decision engine. If a feature only shows data but doesn't clarify a specific decision (e.g., "Should I approve overtime?"), it is incomplete.

## 5. Knowledge
**Does knowledge improve?**
- Does this feature help capture, preserve, or inject institutional wisdom? Does it make the property smarter?

## 6. Coordination
**Does collaboration improve?**
- Does it create operational clarity for everyone affected? Does it use silent coordination instead of noisy notifications?

## 7. Learning
**Does the property become smarter?**
- Are we tracking the outcome of the action taken here to improve future recommendations?

## 8. Complexity
**Can we remove something instead?**
- Before adding a new widget, ask if an existing one can be deleted, simplified, or merged. Reduce cognitive load first.

## 9. Explanation
**Can the OS explain itself?**
- Is the reasoning behind the data or recommendation transparent and understandable to a stressed manager?

## 10. Trust
**Would a GM rely on this?**
- If a seasoned General Manager wouldn't trust this feature to run their Friday dinner service, it is not ready for production.
